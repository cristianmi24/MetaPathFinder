Guía Completa de Imágenes y Diagramas

Este documento indica exactamente qué capturas de pantalla y diagramas debes generar, con los nombres de archivo recomendados y el código PlantUML listo para copiar y renderizar. Actualizado con el motor híbrido de ML (Árbol de Decisión + Random Forest) y micro-cápsulas personalizadas.

1. Lista de Imágenes 2. Diagrama de Casos de Uso 3. Diagrama de Arquitectura 4. Instrucciones de Inclusión

1. Imágenes / Capturas de Pantalla Requeridas

Total recomendado: 9–11 figuras. Todas las imágenes deben guardarse en una carpeta figuras/ (o images/) dentro del mismo directorio del archivo .tex.

FIGURA 1 Diagrama de Casos de Uso
Obligatoria
Nombre de archivo recomendado:
figura1_casos_de_uso.png
Qué capturar / generar:
Diagrama PlantUML de Casos de Uso completo (ver sección 2). Usa PlantUML, StarUML o draw.io. Exporta a 1200–1600 px de ancho.
FIGURA 2 Diagrama de Arquitectura
Obligatoria
Nombre de archivo recomendado:
figura2_arquitectura_sistema.png
Qué generar:
Diagrama PlantUML de Arquitectura (C4 Context + Component o Deployment). Ver sección 3. Incluye Frontend, Backend, Store, Hooks y componentes clave.
FIGURA 3 Interfaz de Juicio (PreTest / Perception)
Nombre recomendado:
figura3_interfaz_juicio_perception.png
Instrucción de captura:
Abre /pretest o la fase de juicio de un reto. Captura la pantalla completa donde el estudiante selecciona su nivel de confianza (1-10 o escala JOL). Incluye el prompt metacognitivo.
FIGURA 4 Reto Interactivo en Ejecución
Nombre recomendado:
figura4_reto_interactivo_ejemplo.png
Instrucción:
Captura uno de los componentes más visuales: TimelineGame, CodingIDEBoard, PhoneDismantlingBoard o DragAndDropBoard mientras el estudiante lo está usando. Muestra la interfaz del reto + barra de progreso o tracking si es visible.
FIGURA 5 Estado Cognitivo / CognitiveBrain
Nombre recomendado:
figura5_estado_cognitivo_tiempo_real.png
Instrucción:
Captura el componente CognitiveBrain (el cerebro animado que aparece en casi todas las pantallas) o el panel lateral de métricas de carga cognitiva y calibración cuando se actualiza en tiempo real.
FIGURA 6 Freno Metacognitivo o Estrategia
Nombre recomendado:
figura6_freno_metacognitivo_estrategia.png
Instrucción:
Provoca intencionalmente un fallo doble en un reto para que aparezca la pantalla de humility_tip, bloqueo de tema o la vista de StrategyMonitor con una estrategia asignada. Captura el mensaje socrático o el monitor de evidencia.
FIGURA 7 Dashboard de Usuarios Registrados
Nombre recomendado:
figura7_dashboard_usuarios_registrados.png
Instrucción:
Inicia sesión como admin y ve a /registered-users. Captura la vista completa con varias tarjetas de estudiantes + filtros. Ideal si tienes 4–6 estudiantes de prueba cargados.
FIGURA 8 Modal de Análisis por Estudiante
Nombre recomendado:
figura8_modal_analisis_estudiante.png
Instrucción:
Abre el modal de detalle de un estudiante desde el dashboard. Captura la tabla de métricas por pregunta, gráficos de Recharts (si aparecen) y las estadísticas agregadas (tiempo, clics, score).
FIGURA 9 Visualizaciones Analíticas (Gráficos)
Nombre recomendado:
figura9_graficos_analiticos_calibracion.png
Instrucción:
Captura específicamente las secciones de gráficos del Dashboard o Analytics: scatter de calibración, heatmap interno, líneas de tendencia, o distribución de estados cognitivos.
FIGURA 10 Micro-cápsula Personalizada Recomendada
Nueva - ML
Nombre recomendado:
figura10_microcapsula_recomendada.png
Instrucción de captura:
Diseña o simula la pantalla que aparece después de la clasificación del Árbol de Decisión. Debe mostrar claramente: Perfil detectado (ej: "Sobreconfiado"), Justificación breve y el video / recurso de micro-cápsula (puede ser un placeholder de YouTube embebido o tarjeta de recurso). Esta es una de las figuras más importantes para la sustentación.
FIGURA 11 Importancia de Variables (Random Forest)
Nueva - ML
Nombre recomendado:
figura11_importancia_variables_randomforest.png
Instrucción:
Genera (en Python con matplotlib/seaborn o en la interfaz futura) un gráfico de barras horizontal con la feature importance del Random Forest. Variables típicas: Tiempo de respuesta, Confianza inicial, Tema, Latencia entre interacciones, Nivel de dificultad, etc. Esta figura es excelente para demostrar rigor científico en la sustentación.
FIGURA 12 (opcional) Flujo Completo de Evaluación o Camino del Árbol de Decisión
Nombre recomendado:
figura12_flujo_evaluacion_o_camino_arbol.png
Captura del flujo completo o (idealmente) una visualización del camino que siguió el Árbol de Decisión para un estudiante concreto. Muy potente para la defensa oral.

Cómo generar la imagen: 1. Copia el código (sin los ```plantuml). 2. Pégalo en https://www.plantuml.com/plantuml/uml/ o usa la extensión PlantUML en VS Code / IntelliJ. 3. Exporta como PNG (recomendado 1400–1800 px de ancho) y guárdalo como figura1_casos_de_uso.png.
⚠️ Corrección importante sobre el actor "Docente / Facilitador":
En la versión actual del sistema, el estudiante inicia la evaluación por sí mismo (es un flujo self-service). El Docente/Facilitador no inicia evaluaciones. Su rol es principalmente de supervisión y consulta de resultados de su grupo. Por eso en el código PlantUML actual ya está comentada la línea que lo conectaba a "Iniciar Evaluación".

3. Código PlantUML — Diagrama de Arquitectura

plantuml-arquitectura.puml (Vista de Contenedores + Componentes principales) 
```plantuml
@startuml MetaPathFinder_Arquitectura
!define C4Container https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml
!include C4Container

skinparam linetype ortho

title MetaPathFinder - Arquitectura de Contenedores y Componentes Principales\n(Incluye Motor Híbrido de ML: Árbol de Decisión + Random Forest)

Person(estudiante, "Estudiante", "Usuario final que realiza evaluaciones metacognitivas")
Person(investigador, "Investigador / Admin", "Analiza datos, ejecuta experimentos y exporta resultados")

System_Boundary(c1, "MetaPathFinder - Frontend (React 19 + Vite)") {
    Container(spa, "Single Page Application", "React 19 + TypeScript + Tailwind + Framer Motion", "Interfaz diferenciada por rol (Auth / Student / Admin Layout)")
    
    Container(store, "Cognitive Store (Zustand)", "Zustand + persist middleware", "Estado global: métricas cognitivas, eventos, estudiantes, sesión actual")
    
    Container(hook_tracking, "useCognitiveTracking", "Custom Hook", "Monitoreo pasivo: visibilidad, scroll, ratón, pausas, latencias")
    
    Container(board_lib, "Interactive Boards Library", "30+ componentes React", "TimelineGame, CodingIDEBoard, PhoneDismantlingBoard, EssayBoard, DragAndDropBoard, etc.")
    
    Container(ui_analytics, "Analytics & Visualization", "Recharts + Chart.js", "Scatter, Heatmaps, Líneas de tendencia, Mapas de calor, Feature Importance")
    
    Container(microcapsule_ui, "Micro-capsule UI", "React Component", "Visualización de micro-cápsula recomendada según perfil ML")
}

System_Boundary(c2, "Backend (Node.js / Express)") {
    Container(api, "REST API", "Express + TypeScript", "POST /api/tracking/events\nGET /api/cognitive/state/:userId")
    Container(static, "Static File Server", "Express static", "Sirve frontend/dist (SPA) en producción (Railway)")
}

System_Boundary(ml, "Capa de Aprendizaje Automático (Python / scikit-learn)") {
    Container(dt, "Decision Tree Classifier", "scikit-learn\n(Reglas exportadas o API)", "Clasificación en tiempo real del perfil metacognitivo\n(Sobreconfiado / Subestimado / Calibrado / Impulsivo...)")
    
    Container(rf, "Random Forest", "scikit-learn\n(Entrenado offline)", "Predicción de riesgo y análisis de feature importance\nsobre datasets acumulados (CSV 40+ estudiantes)")
    
    Container(recommender, "Micro-capsule Recommender", "Motor de reglas + modelo", "Asigna micro-cápsula educativa según perfil del DT")
}

System_Ext(localstorage, "localStorage (Navegador)", "Persistencia del lado cliente", "Datos de sesiones, eventos y resultados")
System_Ext(gemini, "Google Gemini API (futuro)", "IA Generativa", "Interpretación automática de perfiles cognitivos (planeado)")

Rel(estudiante, spa, "Usa", "HTTPS")
Rel(investigador, spa, "Usa", "HTTPS")

Rel(spa, store, "Lee / Escribe estado", "React hooks")
Rel(spa, hook_tracking, "Activa globalmente", "useEffect + listeners")
Rel(store, hook_tracking, "Recibe eventos cognitivos", "")
Rel(spa, board_lib, "Renderiza retos dinámicamente", "componentMap por challengeId")
Rel(spa, ui_analytics, "Muestra visualizaciones", "")
Rel(spa, microcapsule_ui, "Muestra micro-cápsula\nrecomendada", "Tras clasificación ML")

Rel(spa, api, "Envía eventos de tracking\n(opcional)", "POST /api/tracking/events")
Rel(api, static, "Sirve archivos estáticos", "")

Rel(store, localstorage, "Persiste automáticamente\n(Zustand persist)", "JSON")

' Flujo ML en tiempo real (futuro)
Rel(spa, dt, "Envía features del estudiante\n(Confianza, Resultado, Latencia, Tema...)", "HTTP / WebSocket (futura)")
Rel(dt, recommender, "Devuelve perfil + micro-cápsula", "")
Rel(recommender, spa, "Retorna recomendación", "")

' Flujo Batch
Rel(investigador, rf, "Exporta CSV → Entrena / Predice", "Offline / Jupyter o servicio batch")
Rel(rf, ui_analytics, "Devuelve feature importance\ny predicciones de riesgo", "")

Rel(investigador, ui_analytics, "Explora métricas científicas", "")
Rel(investigador, api, "Exporta datos estructurados", "")
```

4. Cómo incluir las imágenes y diagramas en el LaTeX

Paso a paso recomendado

  1. Crea una carpeta llamada figuras (o images) al lado de tu archivo .tex.
  2. Guarda todas las capturas de pantalla con los nombres exactos indicados arriba.
  3. Genera los dos diagramas PlantUML y guárdalos como:
    • figura1_casos_de_uso.png
    • figura2_arquitectura_sistema.png
  4. En el archivo MetaPathFinder_Documentacion_Software.tex, las figuras ya tienen placeholders con \fbox. Reemplaza cada bloque por el código estándar de inclusión:
\begin{figure}[H]
  \centering
  \includegraphics[width=0.92\textwidth]{figuras/figura1_casos_de_uso.png}
  \caption{Diagrama de casos de uso del sistema MetaPathFinder...}
  \label{fig:casos-uso}
\end{figure}
Recomendación importante:
Para que las figuras se vean profesionales, todas las capturas de pantalla deben tener el mismo ancho (recomendado 1400–1600 px) y recortarse limpiamente (sin barras del navegador ni elementos de la interfaz del SO). Usa herramientas como ShareX, Flameshot o Snipping Tool con modo "recorte rectangular preciso".
